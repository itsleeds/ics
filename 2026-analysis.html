PCT / LCWIP Data Ingest & Funding Analysis (2026)

REF 2029 impact case study — England proof-of-concept

Author

Tom Auer

Published

September 3, 2026

1 Overview

This document reports the results of the 2026 re-run of the data-ingest process that collects evidence of the Propensity to Cycle Tool (PCT) and related active-travel planning tools in English Local Cycling and Walking Infrastructure Plans (LCWIPs) and related documents, integrated with official Active Travel Fund (ATF) allocation data.

The 2026 run is a proof-of-concept for England (the first stage before an international roll-out). It improves on previous (~2024) work in four key ways:

  1. Distinction between LCWIP reports and related material — each document is classified LCWIP, LCWIP-related, or other, a distinction the previous work did not make.
  2. Richer “how PCT was used” detail — explicit scenario usage (Go Dutch, Government Target, E-bike, Go Cambridge), data sources, desire-line usage, and prioritisation-integration flags.
  3. Reproducible pipeline — every web page / PDF is downloaded to data-govuk-2026-raw and a .md text extract written to data-govuk-2026-md; structured fields are extracted with a single, unlimited local engine (Ollama gemma4-12b-hermes) so the results are fully reproducible without paid API credits.
  4. Integration with Capital & Revenue Funding Data — matching local authority entities to historical ATF funding (2020/21–2024/25) and multi-year future funding allocations (2026–2030) to evaluate how tool adoption aligns with infrastructure investment.

The headline dataset merges the fresh 2026 collection with the existing 94-entry database (LCWIP_database.json), so the release shows how the evidence base has grown.

2 Ingest Methods

  • Discovery. Seed URLs came from the existing 94-entry database, supplemented by web searches for 2024–2026 LCWIPs and related active-travel strategies, plus the Transport for the South East (TfSE) Regional Active Travel Strategy and Action Plan (RATSAP) Evidence Base (June 2025), which contains a 64-LCWIP status log for the South East.
  • Download. Each candidate URL was fetched and stored as a raw file (data-govuk-2026-raw) with a text/markdown extract (data-govuk-2026-md).
  • Extraction. A 21-field schema (schema_2026.json) was applied per document via a local LLM. Outputs are in results/extracted/.
  • Aggregation. Extracted records were merged with the 94-entry database by URL/name and written to results.json and a flat results.csv.

9.2 Entity Reconciliation & Name Matching

To ensure accurate joins between LCWIP reports and funding allocations, local authority names are cleaned and matched using Jaro-Winkler string distance with manual alias rules for reconfigured unitary and combined authorities.

# Extract unique authority names from extraction results
results_names <- results |>
    select(local_authority_name, combined_authority_name) |>
    mutate(name = ifelse(
        !is.na(local_authority_name), 
        local_authority_name, 
        combined_authority_name
    )) |>
    distinct(name) |>
    arrange(name) |>
    filter(!is.na(name))

# Extract names from LTAs and unpack JSON lookup
ltas_names <- ltas |>
    st_drop_geometry() |>
    select(name, lad_lookup) |>
    arrange(name) |>
    rename(name_lookup = lad_lookup)

ltas_lookup_names <- ltas_names |>
    mutate(name_lookup = map(
        name_lookup, 
        ~ fromJSON(.x)$lad_name
    )) |>
    select(name, name_lookup) |>
    unnest(name_lookup)

ltas_lookup_names <- bind_rows(
    ltas_lookup_names,
    ltas_lookup_names |>
        distinct(name) |>
        filter(!name %in% ltas_lookup_names$name_lookup) |>
        mutate(name_lookup = name)
)

# Standardise names by stripping council boilerplate
results_names <- results_names |>
    mutate(name_clean = name |>
        str_remove_all("(?i)city") |>
        str_remove_all("(?i)councils") |>
        str_remove_all("(?i)council") |>
        str_remove_all("Borough") |>
        str_remove_all("(?i)district") |>
        str_remove_all("(?i)county") |>
        str_remove_all("(?i)of") |>
        str_remove_all("(?i)the") |>

        str_remove_all("(?i)royal") |>

9.4 Integrated Metric Construction

We aggregate document observations, depth-of-use scores, desire-line usage, and total funding amounts:

analysis <- ltas_lookup_names |>
    select(name) |>
    distinct(name) |>
    arrange(name)

results_analysis <- results |>
    left_join(
        results_names |> select(local_authority_name = name, ltas_name),
        by = "local_authority_name"
    )

analysis_data <- analysis |>
    left_join(
        results_analysis |>
            mutate(pct_usage_depth = parse_number(as.character(pct_usage_depth))) |>
            group_by(ltas_name) |>
            summarise(
                n_observations = n(),
                n_mentions_pct = sum(n_mentions_pct, na.rm = TRUE),
                pct_usage_depth_1 = sum(pct_usage_depth == 1, na.rm = TRUE),
                pct_usage_depth_2 = sum(pct_usage_depth == 2, na.rm = TRUE),
                pct_usage_depth_3 = sum(pct_usage_depth == 3, na.rm = TRUE),
                n_pct_desire_lines_used = sum(pct_desire_lines_used, na.rm = TRUE)
            ),
        by = c("name" = "ltas_name")
    ) |>
    left_join(
        atf_names |> select(name, atf20_21, atf21_22, atf22_23, atf23_24, atf24_25),
        by = "name"
    ) |>
    left_join(
        atf_future_names |> select(name, cdel_per_year_4yr, rdel_per_year_3yr, total_over_4yr),
        by = "name"
    ) |>
    mutate(across(
        c(atf20_21, atf21_22, atf22_23, atf23_24, atf24_25, cdel_per_year_4yr, rdel_per_year_3yr, total_over_4yr),
        ~ {
            x <- stringr::str_squish(as.character(.x))
            x[stringr::str_detect(x, stringr::regex("^invalid\\s*number$", ignore_case = TRUE))] <- NA_character_
            readr::parse_number(x)
        }
    ))

funding_5yr_cols <- c("atf20_21", "atf21_22", "atf22_23", "atf23_24", "atf24_25")

analysis_metrics <- analysis_data |>
    mutate(
        n_observations = replace_na(n_observations, 0),
        n_mentions_pct = replace_na(n_mentions_pct, 0),
        n_pct_desire_lines_used = replace_na(n_pct_desire_lines_used, 0),
        pct_usage_depth_1 = replace_na(pct_usage_depth_1, 0),
        pct_usage_depth_2 = replace_na(pct_usage_depth_2, 0),
        pct_usage_depth_3 = replace_na(pct_usage_depth_3, 0),
        n_depth_scored = pct_usage_depth_1 + pct_usage_depth_2 + pct_usage_depth_3,
        depth_score_mean = if_else(
            n_depth_scored > 0,
            (1 * pct_usage_depth_1 + 2 * pct_usage_depth_2 + 3 * pct_usage_depth_3) / n_depth_scored,
            NA_real_
        ),
        total_over_5yr = if_else(
            rowSums(!is.na(across(all_of(funding_5yr_cols)))) > 0,
            rowSums(across(all_of(funding_5yr_cols)), na.rm = TRUE),
            NA_real_
        ),
        pct_mention_rate = if_else(n_observations > 0, n_mentions_pct / n_observations, NA_real_),
        desire_lines_rate = if_else(n_observations > 0, n_pct_desire_lines_used / n_observations, NA_real_)
    )

10 Limitations & Next Steps

  • Geographic scope: This 2026 run covers England only; international tools (NPT Scotland, CRUSE Ireland, biclaR Portugal, Norway PCT) are the focus of subsequent analysis stages.
  • Normalisation by authority scale: Funding allocations are heavily influenced by local authority population and geographic scale; further work will normalise funding per capita.
  • Validation: doc_type and free-text fields are model-extracted; key quotes and scoring should be spot-checked against source PDFs.
  • Reproducibility: Extraction can be re-run locally with scripts/run_extract_ollama.py without external paid API credits.
